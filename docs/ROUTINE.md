# Плановая облачная сессия: следующая задача из очереди

Тебя запускает рутина по расписанию. Работаешь сам, никого не спрашиваешь, в конце коротко отчитываешься.

1. `git fetch origin`. Работай от свежего `origin/hospital`. В `main` не пушить никогда: main — это выкладка
   на сайт, её делает владелец с мака после проверки. `tools/stamp.mjs` не запускать.
2. Прочитай `docs/CLOUD.md` целиком (правила, проверка, очереди) и `docs/NIGHT.md`. Звук не трогать
   (`engine-audio.js`, `carfx.js`, `data/audio/`).
3. Выбери задачу: иди по разделам «Очередь, часть 2», «часть 3», «часть 4», «часть 5», «часть 6» сверху вниз.
   - Задача занята или сделана, если на origin уже есть её ветка `cloud/<имя>` (`git branch -r`) или в
     `docs/handoff/` есть её записка.
   - Имена веток: 13 → `cloud/univ`, 14 → `cloud/tolstogo`, 15 → `cloud/plinths`, 16 → `cloud/fuel-overlap`,
     17 → `cloud/map-touch`, 18 → `cloud/facades`, 28 → `cloud/chernomorka`, 29 → `cloud/bmorskaya`; для новых пунктов — `cloud/<короткое-имя>`.
   - В «части 4» (по одному зданию) несколько сессий стартуют одновременно: начни не с первого пункта, а со
     случайного (`shuf`), и если `git push` пустого WIP-коммита в `cloud/m-<id>` отклонён (ветку уже взяли) —
     сразу бери следующий свободный пункт.
   - Возьми первую свободную. Сразу создай ветку от `origin/hospital` и запушь её пустым коммитом
     «WIP: <пункт>», чтобы другая сессия её не взяла.
4. Если свободных задач нет — ничего не делай, не пушь, ответь «очередь пуста».
5. Сделай задачу по описанию в CLOUD.md.
   - Ничего не выдумывать про город: только данные OSM из репозитория (`data/world.json` и т. п.). Внешнего
     интернета у тебя нет.
   - Новое — новым модулем с минимальной врезкой в `main.js`.
   - Скорость: не больше +5% вызовов отрисовки и треугольников.
6. Проверка лёгкая: браузер без видеокарты медленный, полный `qa.mjs` не гонять.
   - `node --check` изменённых файлов;
   - если есть Playwright — 1–2 снимка своего места, открыть и посмотреть;
   - нет ошибок в консоли.
7. Записка `docs/handoff/<ветка-через-дефис>.md`: что сделано, тронутые чужие файлы и места, как проверить,
   что осталось. Коммить кусками, пушь свою ветку. Сборку `cloud/wave` не делай — её ведёт сборщик.
8. Отчёт одним абзацем: какая задача, что сделано, ветка.
